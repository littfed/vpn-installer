# 02: Реестр здоровья нод и логика Circuit Breaker

**What to build:**
Модуль учета состояния здоровья нод (`node-health.json`) и логика Circuit Breaker с защитой от флаппинга. Отслеживает историю последовательных сбоев и успехов по каждому протоколу каждой ноды пула, рассчитывая итоговый статус доступности (`healthy`, `degraded`, `offline`).

**Blocked by:** 01: Движок синтетического зондирования на базе sing-box

**Status:** ready-for-agent

## Acceptance criteria

- [ ] Файл состояния `/opt/vpn-installer/node-health.json` хранит статус каждого протокола каждой ноды:
  - `status`: `"healthy"` | `"degraded"` | `"offline"`
  - `consecutive_failures`: целое число
  - `consecutive_successes`: целое число
  - `last_latency_ms`: время отклика в мс
  - `last_checked`: временная метка ISO 8601
  - `history`: краткий скользящий лог последних 5 проверок (статус + время отклика)
- [ ] Логика Circuit Breaker:
  - При возникновении сбоя (таймаут, сброс TCP, недоступность целевого ресурса) инкрементируется `consecutive_failures`, а `consecutive_successes` сбрасывается в 0.
  - При достижении `consecutive_failures >= 2` статус протокола переходит в `"degraded"`.
  - При успешном тесте инкрементируется `consecutive_successes`, а `consecutive_failures` сбрасывается в 0.
  - Только при достижении `consecutive_successes >= 2` протокол возвращается в статус `"healthy"`.
  - Если все протоколы ноды деградировали, общий статус ноды переходит в `"offline"`.
- [ ] Атомарная запись файла состояния (запись во временный файл + замена через `os.replace` или `mv`), исключающая повреждение JSON при параллельном чтении другими процессами.
- [ ] Обеспечивается устойчивость к отсутствию или повреждению предыдущего файла `node-health.json` (автоматическая инициализация).
